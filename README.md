# Oleksandr Career Hub

Публичный портал рекрутера: вакансии, честное описание процесса, профиль и база материалов для кандидатов. Работает как статический сайт на GitHub Pages и устанавливается как офлайн‑приложение.

> Сейчас проект содержит **явно помеченные демо‑вакансии** и закрыт от поисковой индексации. Не отправляйте ссылку кандидатам, пока не замените примеры реальными данными.

## Что уже работает

- адаптивная страница рекрутера без внешних шрифтов, трекеров и CDN;
- поиск, фильтры и сортировка вакансий;
- прямые ссылки на вакансии;
- избранное и сравнение до трёх позиций;
- личные заметки, которые остаются только в браузере кандидата;
- полезные памятки с печатью / сохранением в PDF;
- готовые email‑отклики без встроенного сбора персональных данных;
- PWA‑установка и офлайн‑доступ после первого успешного открытия;
- понятный индикатор сети и безопасное обновление service worker;
- автоматическая проверка контента и публикация через GitHub Actions;
- доступная клавиатурная навигация, skip‑link, mobile‑меню и reduced motion.

Отправка email, открытие GitHub/LinkedIn и получение обновлений требуют интернета. Первый визит тоже требует сети — браузер не может скачать сайт заранее.

## Быстрый запуск

Нужен Node.js 20+ только для проверки. Сам сайт не требует сборки.

```bash
npm test
npm start
```

Можно использовать любой локальный HTTP‑сервер. Service worker не работает при открытии `index.html` через `file://`.

## Как заменить демо на свои данные

Весь редактируемый контент находится в [`data/content.js`](data/content.js).

1. Заполните `profile`: полное имя, специализация, регион, рабочая почта и проверяемые профили.
2. Удалите объекты с `demo: true` из массива `jobs`.
3. Добавьте реальные вакансии по существующей структуре.
4. Укажите вилку, валюту, `gross/net`, формат договора, часовой пояс и дату проверки.
5. Переключите `site.isDemo` на `false`.
6. Обновите `site.baseUrl`, заголовок и описание.
7. В `robots.txt` замените `Disallow: /` на `Allow: /`.
8. Обновите дату в имени кэша `CACHE_VERSION` внутри `sw.js`, если менялся набор файлов.
9. Выполните `npm test`.

Для каждой реальной вакансии обязательно сохраните:

- причину открытия роли;
- задачи, обязательные требования и «будет плюсом» раздельно;
- зарплатную вилку или честную причину её отсутствия;
- формат, локацию, часовой пояс и договор;
- этапы, длительность и ожидаемый срок решения;
- дату последней проверки и рабочий способ отклика.

## Публикация на GitHub Pages

1. Создайте публичный репозиторий, например `talent-hub`.
2. Загрузите проект в ветку `main`.
3. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
4. Workflow `.github/workflows/pages.yml` проверит контент и опубликует сайт.
5. Откройте `https://ВАШ-ЛОГИН.github.io/talent-hub/` один раз онлайн и установите приложение через меню браузера.

## Что повышает доверие

- настоящее имя, фото и проверяемые рабочие контакты;
- видимые дата и статус каждой вакансии;
- фраза «для кандидатов бесплатно» и предупреждение о мошенничестве;
- конкретные сроки ответа без обещания гарантированного оффера;
- объяснение конфиденциальных поисков;
- отзывы только с разрешением и контекстом, без вымышленных цифр;
- спокойная тональность и возможность задать вопрос без резюме;
- прозрачная политика данных и кнопка удаления локального состояния.

Не публикуйте неподтверждённые бейджи, фальшивую срочность, стоковые отзывы и метрики без методики.

## Приватность и границы проекта

Этот репозиторий должен содержать только публичные вакансии и материалы. **Никогда не добавляйте сюда резюме, телефоны, паспорта, заметки об интервью или выгрузки ATS**: Git хранит историю, и обычное удаление файла не гарантирует удаление данных.

GitHub Pages не является защищённой CRM. Для хранения персональных данных кандидатов используйте отдельную систему с авторизацией, сроками хранения, журналом доступа и процедурой удаления.
